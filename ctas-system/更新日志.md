## 2026-11-26 · 修复：每次重启法规库被夹具覆盖

**问题**：启动时「残本法规去重」按「去掉全部括注后的基名」判同一法规，把《最高人民法院 最高人民检察院关于办理贪污贿赂刑事案件适用法律若干问题的解释》与《……解释（二）》判为同一部，删掉条数较少的前者；随后演示数据加载发现条文数少于夹具，便整库删除、按夹具重载。结果每次重启法规库都被夹具覆盖：条款 ID 全部变化，夹具导出后在界面上新增 / 修改 / 入库的法规在重启后丢失。

**修改**

- 夹具只在法规库为空时建库（新部署）；已有法规库是主本，启动时不再覆盖，与夹具不一致时只在日志中提示。确需以夹具覆盖时显式执行 `docker exec ctas python -m app.demo_data --reset-regulations`（`app/demo_data.py`）。
- `platform_check.py` 新增「法规库 · 重启不覆盖法规库（界面修改保留）」：先经界面入库一部法规，再执行启动时的去重与夹具加载，要求法规与条款 ID 不变。

## 2026-11-26 · 部门（租户）管理：功能模块 + 数据范围 + 业务数据隔离

**要求**：分为多个部门，每个部门多个账号；不同部门可见的功能模块不同；业务数据相互隔离（法规知识库等通用能力共享）；管理员在界面上管理各部门的功能模块与数据范围。

**模型**
- 部门 = 租户。每个账号归属一个部门；部门配置「功能模块」与「数据范围」（本部门 / 本部门 + 指定部门 / 全部部门）。平台管理员（admin 角色）不受限。
- 角色改称岗位（平台管理员 / 信访岗 / 办案岗 / 审理岗），只决定模块内可办理的操作；看得到哪些模块、哪些数据由部门决定（原来按角色写死在导航和工作台里）。
- 业务数据按部门归属：信访、线索 / 案件、讯问、审理、送审材料、申诉、党风、巡察、监督数据集与自建模型、预警与督办、资金流水、廉政档案、文书与版本、谈话录音、档案、智能体会话共 24 张表加 `dept_id`，新建时自动归经办人部门，子表随父记录。法规库、文书模板、校验规则、历史报告库、审计日志全平台共享；内置监督模型为平台共享配置。
- 跨部门移交：信访转线索、移送审理、党风 / 巡察移交时，新记录归**承办部门**（本部门可承办则留在本部门；只有一个部门开通该业务时自动确定；多个时由经办人在弹窗中选择），并写入「移交授权」——承办部门可查阅来源记录、来源部门可跟踪办理结果，只对这一条记录生效，不必为流转放开整个部门的数据范围。

**实现**
- 隔离在 ORM 层统一施加（`app/tenancy.py`：SQLAlchemy `do_orm_execute` + `with_loader_criteria`），覆盖列表、详情（`get`）、统计（count / group by）、批量 update / delete，30 多个路由无需逐个改查询，新增接口默认即隔离。范围挂在请求的 Session 上；启动脚本与后台任务为系统上下文。
- 接口按模块把关：未开通模块的接口直接 403（不只是隐藏菜单）；页面跨模块调用（审理页查案件、取类案等）按前端实际调用列入白名单。审计日志接口改为仅平台管理员（原来任何登录用户都可读全部审计记录）。
- 全局唯一编号改为跨部门取号（申诉编号原按可见记录计数，隔离后会发重号）；廉政档案人员、预警指纹、误报反馈改为「部门内唯一」（各部门各自建档 / 各自预警），预警归关联业务对象所在部门。
- 业务平台 MCP：支持部门级令牌（在部门配置中生成，只显示一次），智能体经 MCP 只能查到该部门数据范围内的数据；`.env` 的 `CTAS_MCP_TOKEN` 保留为平台级令牌（全部部门）。
- 升级：首次启动自动建立默认部门（系统管理部门 / 信访室 / 审查调查室 / 案件审理室），按角色把已有账号归入部门；已有数据按经办人部门、业务归口回填归属，历史移交链（信访→线索、案件→审理、党风 / 巡察→线索）补齐授权。幂等。

**界面**
- 新增「系统管理 → 部门与权限」：部门列表（账号数、模块、数据范围、名下数据量、MCP 令牌）；配置抽屉（基本信息、按分组勾选模块、数据范围 + 按未保存配置实时预览可见数据量、MCP 令牌、部门账号）；「模块权限矩阵」（模块 × 部门直接勾选，立即生效）；「移交授权」记录。
- 用户管理：所属部门列与筛选，建账号必须选部门（初始密码至少 8 位），可编辑部门 / 角色、重置密码。
- 导航、页面路由、工作台分区与快捷入口按部门模块生成；直接输入未开通模块的地址显示「无权访问」。进入系统时刷新部门权限，管理员调整后无需重新登录。
- 转线索、移送审理、党风 / 巡察移交在有多个承办部门时弹出选择，成功提示显示承办部门。
- 宿主机无 Node.js 时用 `scripts/build_frontend.sh` 在容器内构建前端。

**验证**

- 上线：备份业务库（ctas-db 容器内 `/tmp/ctas-before-tenancy.dump`）后重建镜像、重建 ctas / ctas-mcp；启动迁移把三处自然键改为部门内唯一，建立 4 个默认部门，4 个账号归部门，65 条历史数据回填归属，补齐 14 条历史移交授权。

## 2026-11-26 · 法规库真实性核对 + 官方全文入库

**核对方法**：中央纪委国家监委网站、全国人大网、国家法律法规数据库、最高法 / 最高检网站在当前网络均不可达（连接被重置）；改用可达的权威转载源——共产党员网（中组部主办）、新华网（新华社受权发布）、人民网——抓取全文，按「章 / 条」解析后与库内条文去空白、统一标点逐条比对；两源都有的文件交叉核对（一致）。工具与来源清单在 `scripts/law_sources/`。

**发现的问题**
- 《公职人员政务处分法》68 条全部是改写摘要，不是法律原文（如第三十二条被缩成一句）。
- 《中华人民共和国刑法》只有 262 条，缺第三百八十三条（贪污罪）、第三百九十条（行贿罪）等，且为 1997 年文本、未含历次修正案。
- 「中央纪委国家监委案件审理室《××证据指引（试行）》」5 部在公开渠道查不到（公开可查的相关文件只有 2025 年 12 月中央纪委办公厅、国家监委办公厅印发的《调查新型腐败和隐性腐败问题证据指引》，未公开全文），却标为「正式」文档。
- 国监发〔2020〕3号、国监办发〔2018〕1号两个衔接文件确有印发，但未取得可核对的公开全文。
- 纪律处分条例、党内监督条例、巡视工作条例、检举控告工作规则等末条混入网页尾巴（「（新华社北京11月2日电）《人民日报》…」）；纪律处分条例第一百五十八条措辞与官方不一致；事业单位处分规定、国企管理人员处分条例、处分批准权限和程序规定各有 6–7 条与官方不一致。

**处理**
- 更正 8 部（党内监督条例、检举控告工作规则、纪律处分条例、巡视工作条例、政务处分法、事业单位工作人员处分规定、国有企业管理人员处分条例、处分违纪党员批准权限和程序规定）：按条号就地替换为官方全文（保留条款 ID），来源写明网址与核对日期；复核 537 条全部与官方逐字一致。
- 新增 9 部官方全文：监督执纪工作规则（77 条）、问责条例（27）、纪律检查委员会工作条例（59）、派驻机构工作规则（56）、党员权利保障条例（52）、监察官法（68）、党章（总纲 + 55 条）、两高贪污贿赂解释（法释〔2016〕9号，20 条）、贪污贿赂解释（二）（法释〔2026〕6号，24 条）。
- 监察法（2024 修正）、监察法实施条例（2025 修订）：官方原文站不可达，未能逐条比对；监察法已按全国人大常委会修改决定抽查（新增 5 条条号与内容一致、章节一致），实施条例条文完整度与 2021 版相当（非摘要）；来源中注明核对结论，保持现行有效。
- 改标（不再作为问答与知识库依据，来源注明原因）：刑法 →「历史文本」；5 部「证据指引」与 2 个衔接文件 →「未核实」；2 部实务整理 →「参考资料」。
- 问答检索只用「现行有效」法规（检索缓存随效力状态变化自动失效）；Nexent 知识库同步后为 19 部现行有效法规。
- 演示夹具 `fixtures/regulations.json` 更新为核对后的法规库，新部署不会再带回旧文本。改动前数据库已备份（ctas-db 容器内 `/tmp/ctas-before-official-import.dump`）。

**验证**：问答「问题线索处置方式」引用监督执纪工作规则第二十一条原文（此前库中无此规则）；「选拔任用弄虚作假」引用政务处分法第三十二条原文（此前为摘要）；「受贿数额较大」引用法释〔2016〕9号第一条、「介绍贿赂」引用法释〔2026〕6号第十七条。

**未做**：中央纪委网站的「工作提示」「执纪执法业务问答」等栏目文章——该站从本网络不可达；且这类文章属新闻 / 评论作品，不同于法律法规（不受著作权保护），整篇批量入库需取得授权，建议由使用单位通过「导入业务资料」录入经授权的材料。现行《刑法》全文需从全国人大网 / 国家法律法规数据库取得后经「正式文档录入」导入。
